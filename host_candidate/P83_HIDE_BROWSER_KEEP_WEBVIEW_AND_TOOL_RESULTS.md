# P83 Hide browser without interrupting agent in foreground

Inspired by the user-provided Bilibili AI browsing screenshots: browser can be collapsed to an in-app chat/status pane, then restored. The *same actual Android WebView* stays attached, VISIBLE underneath an opaque overlay (not destroyed, removed, paused, reloaded or replaced), so in-flight evaluateJavascript callbacks, DOM/textarea draft and tool response correlation can proceed while the chat panel is shown. The status label updates actual locally verified steps (not invented status); a button reveals the same WebView. The code explicitly shows non-destructive browser UI controls while prohibiting unsolicited public comments/DM/form submissions.

This is implemented first as a real Android35 P79 file-backed tool result **synthetic offline fixture** in side-by-side independent test package. It is not yet integrated into original MainActivity/BrowserBridge, not an OS overlay requiring SYSTEM_ALERT_WINDOW, and cannot guarantee background execution after navigating away from the activity, stopping the process, OS power restrictions or phone restarts. Browser session persistence across app restarts still requires original app WebView profile/cookies/Storage assessment (P71 had synthetic proof only). The user's screenshot is a visual/behavioral target, not evidence of Bilibili API or production support. Formal same-signature APK remains blocked until original-node readiness and tool_result continuation plus login/approval regressions pass.

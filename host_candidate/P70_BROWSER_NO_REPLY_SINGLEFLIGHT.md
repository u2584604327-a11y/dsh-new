# P70 DSH browser tool shared-mailbox no-reply race repair

Root evidence from P69 [run #41026047441](https://github.com/u2584604327-a11y/dshe/actions/runs/41026047441): exact signed-v138 and pinned P6 browser-tool.zip/lib/index.js implement `sendCommand(home,id,payload,timeoutMs)` over one shared CMD_FILE and RESULT_FILE. Each call unconditionally unlinks RESULT_FILE, writes CMD_FILE and polls reply.id every 80 ms for 25,000 ms. Concurrent calls can delete each other's result, overwrite command and miscorrelate replies. There is NO native executor guarantee here; no reply can also happen when Android never handles the command.

This patch makes sendCommand **in-process single-flight per home**: wait for predecessor before removing result/writing request, cap local queue wait, preserve original request and response schema, ensure payload cannot override host correlation id, ignore stale mismatched reply ids, return distinct typed failure for write/queue/no reply. When a command was dispatched but did not produce a matching reply by deadline, its side effects are unknown: `BROWSER_NO_REPLY_OUTCOME_UNKNOWN`, `retrySafe:false`, mailbox quarantined as `BROWSER_MAILBOX_NEEDS_RESYNC`. **Never automatically replay comment send, click, payment, share or other mutation.** A fresh verified native handshake or process restart is required, not assumed by this code. It will not silently claim the operation was completed.

The patch applies ONLY to exact SHA-pinned P6 nested browser-tool.zip/lib/index.js and produces a separate ephemeral patched browser-tool.zip; all other inner ZIP entries are bytewise preserved. Original P6 archive, signed APK, private signing key, installed app, cookies and user data are unchanged. GitHub CI runs Node tests on *actual patched P6 source* with two overlapping calls, stale reply, total silence, quarantine and independent homes.

Limitations: serialization applies within one browser-tool Node module runtime, not across unrelated processes; actual Android native browser executor and model tool-call dispatcher, Bilibili dynamic comment permissions, and persistent WebView login remain NOT TESTED. To activate this for the installed app, a future original-host integration/ART/device acceptance and signed versionCode>138 update is required. P68 isolated Node/Process fixture is separate, not proof that browser tool now works. Keep Draft.
